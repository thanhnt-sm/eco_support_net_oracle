# Changelog

All notable changes to DataGuard are documented here. Format based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), semantic versioning via git tags (MinVer).

## [Unreleased] — next release must be tagged `v0.3.0`

> The IDE hosts below reject CLI 0.2.2 and older for `validate`/`assess` (no `ide-safe: active`
> handshake) and point users at "0.3.0 or later"; the latest published tag is `v0.2.2`, so the next
> CLI release must be `v0.3.0`. `DataGuard.Cli` is not yet published on nuget.org (owner to reserve
> the ID): install the CLI from GitHub Releases and verify its SHA-256.

### Security
- **VS Code Extension / dependencies (2026-09-30)**: closes the 17 OSV advisories reported by OSSF Scorecard (code-scanning alert #45, `VulnerabilitiesID`) against `src/DataGuard.VSCode/package-lock.json`. All are transitive npm packages of the extension: `undici` 7.29.0 → 7.30.0 (GHSA-2gqq-gqf2-x968, GHSA-2jfj-6hjv-fm6j, GHSA-3wwx-pv8p-q78v, GHSA-3xpg-4rpp-hhhm, GHSA-8436-99hf-9mmv, GHSA-pmjh-fq2x-6v4x, GHSA-r53p-7pc4-xj5r, GHSA-rfgv-xxqx-mfg5, GHSA-rx4f-c7p8-82vq, GHSA-w293-vg96-wgc3; via `@vscode/vsce` → `cheerio`, dev-only), `brace-expansion` 5.0.9 → 5.0.12 (dev, via `@vscode/vsce` → `minimatch@10`) and 2.1.4 → 2.1.7 (shipped in the VSIX via `vscode-languageclient` → `minimatch@5`) (GHSA-6j4f-fj2g-mc7p, GHSA-q2hr-2g5m-vwhr, GHSA-qhr7-859c-m2p7), `fast-uri` 3.1.6 → 3.1.8 (`overrides` pin raised; GHSA-58mr-gqgx-xq4g, GHSA-hrr3-gc8f-f4qj, GHSA-qw65-cvwx-89v3) and `markdown-it` 14.3.0 → 14.3.2 (GHSA-253c-mchw-3w2r). All bumps stay inside the parents' declared semver ranges; `npm audit` and `osv-scanner` report 0 findings. No NuGet or Docker change was needed.
- **CLI (2026-09-29, red-team follow-up)**: `--ide-safe` now prints `ide-safe: active` as the first stderr line (before any option rejection) so hosts can require a positive handshake instead of trusting the absence of an error. New `--allow-env-connection` (`validate` only, no effect without `--ide-safe`) keeps the host-supplied `DATAGUARD_CONNECTION_STRING` credential and nothing else — `.dataguard.yml` connection strings are still stripped, `GroundTruthMode: Manual` is forced to `Snapshot`, and stderr reports `ide-safe: kept environment connection (--allow-env-connection)`. The kept credential is used only to read the ground-truth catalog (schema and stored-procedure definitions): the live SQL-shape rule (`sp_describe_first_result_set` over repository SQL) stays disabled under `--ide-safe`, so `validate` never describes repository SQL against that database; only `verify-shape` does. The process environment is scrubbed after policy application (`DATAGUARD_CONNECTION_STRING` unless kept, `VAULT_TOKEN`, `VAULT_ADDR`, `AWS_*`, `PGPASSWORD`, `MYSQL_PWD`, `ConnectionStrings__*` and every other `DATAGUARD_*` variable except `DATAGUARD_PROVIDER` and `DATAGUARD_CLI_PATH`). Repository config can no longer exhaust the host: `MaxDegreeOfParallelism` is clamped to the processor count, `MaxViolationQueueSize` to 100 000 and `ValidationTimeoutSeconds` to 900 s (reported as `Name=value (clamped to bound)`). Every regex in the CLI runs with a 1 s match timeout, and a regex that exceeds it is reported as a rule failure rather than silently dropping that rule's findings; the DG016 select-list regex is non-backtracking; SQL literals over 256 KiB are skipped with `[WARN] DG1291 …` instead of being fed to the rules. Every file output of `validate`, `oracle-check` and `verify-shape` (SARIF, evidence, contracts) now refuses an output path that passes through a reparse point inside the workspace with exit 4 (`Refusing to write … through a symbolic link or invalid path.`), before any work or connection, matching `assess`; a refused `summary.json` is logged instead of silently skipped.
- **Visual Studio Extension (2026-09-29, red-team follow-up)**: results are published only when the CLI acknowledged `ide-safe: active`; "CLI too old" is reported only for a genuine `Unrecognized command or argument '--ide-safe'` rejection (exit 1, no progress events), so a spoofed file name can no longer trigger it, and any other missing handshake discards the results with a distinct message. Consent is keyed by the solution directory, the full `.sln` path and the `.dataguard.yml` hash; new **Forget Solution Consent** command. Because the key changed, every solution is asked for consent once more after upgrading. All `dotnet tool install|update -g DataGuard.Cli` guidance removed (reinstall the extension or point the custom CLI path at a `dataguard.exe` from GitHub Releases, SHA-256 verified).
- **VS Code Extension (2026-09-29, red-team follow-up)**: `validate` passes `--allow-env-connection` only when a SecretStorage credential exists, restoring the documented credential flow under `--ide-safe` without ever honouring a repository connection string; the credential serves ground-truth catalog reads only — `validate` never describes repository SQL against it, only **Verify SQL Shapes Against Database** does, after confirmation. The `ide-safe: active` acknowledgement is echoed as `[INFO]` (other `ide-safe:`/`baseline:` lines stay `[WARN]`), and the read-query count in the **Verify SQL Shapes Against Database** confirmation is computed by a validated helper (`countReadQueries`) instead of a cast of `summary.json` (hardening). `validate`/`assess` results are discarded unless the first stderr line is `ide-safe: active` (`DataGuard CLI did not confirm IDE-safe mode; results were discarded`, plus `Update the dataguard CLI (0.3.0 or later) or set dataguard.cliPath` for an old CLI); the extension never retries without the flag. **Verify SQL Shapes Against Database** now asks for the same modal confirmation as Refresh Snapshot / Create Baseline, naming the masked target host. NuGet install guidance replaced by GitHub Releases + SHA-256.
- **CI / Release (2026-09-29)**: one shared `scripts/assert-vsix.ps1` gate (required entries `cli/dataguard.exe`, `DataGuard.Analyzers.dll`, `DataGuard.CodeFixes.dll`, `extension.vsixmanifest`, `DataGuard.VisualStudio.dll`, `DataGuard.VisualStudio.pkgdef`, manifest version check) runs after the MSBuild packaging step in both `ci.yml` and `release.yml`; `release.yml` runs the Visual Studio unit tests before packaging; CI uploads the VSIX artifact (now named with the commit SHA) only for same-repository branches — fork pull requests still build and assert but never publish an unsigned VSIX. `scripts/check-workflow-policy.py` asserts these invariants and runs in the CI `build-and-test` job. New `cli-package` release job publishes framework-dependent CLI packages `dataguard-<version>-<rid>.zip` (`win-x64`, `linux-x64`, `osx-arm64`) with a `.sha256` next to each, attached to the GitHub Release and covered by the build-provenance attestation.

- **CLI (2026-09-29)**: new `--ide-safe` option on `validate` and `assess`. Forces Snapshot mode and strips `ManualAssemblyPath`, connection strings (config and `DATAGUARD_CONNECTION_STRING`), secret-manager settings, `AuditLogPath` and telemetry output from repository-controlled configuration; rejects `--connection`, `--offline`, `--assembly`, `--ef-*`, `--allow-network`, `--remote-advisories` with exit code 2. Closes the path where a hostile `.dataguard.yml` could make an IDE-launched CLI call `Assembly.LoadFrom` or authenticate to an attacker host.
- **Visual Studio Extension (2026-09-29)**: per-solution trust gate — first run asks for consent, stored per (solution directory, SHA-256 of `.dataguard.yml`) in the VS user settings store; "Run Validation on Build" never prompts and skips unconsented solutions. CLI is always launched with `--ide-safe`; an older CLI that rejects the flag stops the run instead of falling back. Removed the unprompted `dotnet tool install -g DataGuard.Cli` auto-install. Custom CLI path must be absolute (no solution-relative resolution). All exception messages written to the Output pane are redacted; redaction now covers `User Id=…;Password=…` forms and JWT-shaped tokens.

- **VS Code Extension (2026-09-29)**: `validate` and `assess` now pass `--ide-safe` in addition to the existing workspace-trust gate, so a tampered `.dataguard.yml` in a trusted workspace can no longer load assemblies or open connections.

### Added
- **CI (2026-09-29)**: new `installers.yml` (**Build Installers**) workflow builds the framework-dependent CLI zips (`win-x64`, `linux-x64`, `osx-arm64`), the VS Code VSIX (with the bundled language server) and the Visual Studio VSIX on every push to `main` and on manual dispatch, each with a `.sha256`, and publishes them to the rolling `nightly` GitHub pre-release (previous `nightly` release and tag are replaced; `v*` releases are untouched). Version defaults to `<ExtensionVersion.Fallback>-nightly.<yyyyMMdd>.<run_number>`; a manual run may pass a plain SemVer, which is also written into the VSIX manifest. The Visual Studio job runs the unit tests first and the shared `scripts/assert-vsix.ps1` gate after packaging; `scripts/check-workflow-policy.py` now covers the new workflow.
- **CI (2026-09-29)**: `visual-studio-vsix-package` job runs the real VSSDK packaging build (`CreateVsixContainer=true`) on every push/PR and asserts the VSIX contains `cli/dataguard.exe`, the Roslyn analyzers, the pkgdef and a manifest version matching `ExtensionVersion.Fallback`. CreatePkgDef regressions no longer wait for a release tag.
- **Visual Studio Extension (2026-09-29)**: Output pane warns when the solution has no `.dataguard.yml` (source-only rules ran); exit code 3 is explained as "validation incomplete" with the CLI reason; Help → About and log banner report the real manifest version.

- **Visual Studio Extension (2026-09-28)**: Error List navigation opens the document via `VsShellUtilities.OpenDocument` with fallback to document/project opening (caret positioning added 2026-09-29, see Fixed).
- **Visual Studio Extension (2026-09-28)**: Bundled Roslyn analyzers (`DataGuard.Analyzers.dll`) and code fixes (`DataGuard.CodeFixes.dll`) into VSIX container via MSBuild target and manifest asset declarations for out-of-the-box IDE squiggles.
- **Visual Studio Extension (2026-09-28)**: Output Window logs rule inventory summary banner (`DataGuard: Ran N rules across M unique check types`) after validation completion.
- **Core SQL Source (2026-09-28)**: Stored procedure heuristic detection in `ProjectCSharpSqlSource.IsSqlString` expanded to support `PROC_`, `FNC_`, and `P_` prefixes alongside existing `SP_` and `USP_`.
- **Oracle Adapter (2026-09-28)**: Enriched `DG010` dialect incompatibility messages now explicitly display target provider and migration syntax hint in visible text.
- `DataGuard.Contracts` package (netstandard2.0): `SkipContractCheck`, `ExpectedSpParameter`, `ExpectedColumn` attributes usable by quick-fixes in consumer projects.
- Manual ground-truth mode: `dataguard validate --offline --assembly <dll>` reads expected columns/parameters from attributes (zero DB access).
- Snapshot mode persists ground-truth schema; offline `validate` rebuilds rules from the snapshot; `snapshot diff --fail-on-drift` exits non-zero on drift.
- Oracle stored-procedure extraction wired into `validate` (ALL_PROCEDURES enumeration, overload grouping by SUBPROGRAM_ID/OVERLOAD).
- MySQL/PostgreSQL SP extraction wired into `validate`.
- Analyzer tests: descriptor arity guard + incremental generator execution tests; strict golden-corpus `unexpectedErrors` assertion; per-rule coverage tests for MY/PG/Oracle dialect rules.
- CI: security gates (vulnerability JSON gate, TruffleHog, CodeQL) now run on tag releases; Docker smoke test runs on PRs; dependabot tracks NuGet; restores run in `--locked-mode`.
- `packages.lock.json` for reproducible restores; MinVer versioning from git tags; SourceLink + deterministic builds; symbol (snupkg) publishing.
- `dataguard config` full round-trip via YamlDotNet (30+ fields, nested Oracle/SqlServer blocks).
- MySql/PostgreSql adapter unit tests: dialect checker (syntax detection, context-aware) + length mismatch detector (12 tests each, no DB required).
- DataGuardApi surface tests: Version, CreatePipeline, WithRules, WithPlugins, ValidationResult/DriftReport computed properties, DataGuardFactory methods (15 tests).
- RulePluginManager tests: null directory, merge built-in rules, get by ID, metadata, dispose, empty directory (7 tests).
- SqlServerIntegrationTests: Testcontainers MsSql, auto-skip when Docker unavailable.

### Fixed
- **Dependabot / VSIX build (2026-09-30)**: the weekly NuGet update job had failed since 2026-09-23 with `dependency_file_not_found` because `Microsoft.VSSDK.BuildTools` imports `tools/vssdk/Microsoft.VSSDK.targets` while the package ships `Microsoft.VsSDK.targets`; on Dependabot's Linux updater the case-sensitive lookup is MSB4019 when `DataGuard.VisualStudio.csproj` is evaluated post-restore through `DataGuard.VisualStudio.Tests`. `VSSDKBuildToolsAutoSetup` is now set only when `$(OS)` is `Windows_NT` (VSIX packaging is Windows-only), and the ubuntu `build-and-test` job gained a **Linux evaluation parity (Dependabot)** step that evaluates the VSIX project the same way in locked mode, so a future Windows-only import fails in CI instead of a week later in Dependabot.
- **VSIX build (2026-09-29)**: the `BuildAnalyzers` target in `DataGuard.VisualStudio.csproj` ran `Restore;Build` in one MSBuild task, so on a clean checkout `DataGuard.Analyzers`/`DataGuard.CodeFixes` compiled from a pre-restore evaluation without the netstandard2.0 reference assemblies (`CS0518 Predefined type System.String is not defined`). The CI "Visual Studio VSIX Packaging Gate" and the marketplace "Package Visual Studio Extension" job had failed on every clean run since this target was introduced; it passed locally only because `obj/` was warm. Restore and Build are now separate MSBuild calls with a unique `MSBuildRestoreSessionId`. The `VsixAnalyzerPackagingTests` now search `bin/Release` recursively, so they assert against the real VSIX instead of silently skipping.
- **CLI (2026-09-29)**: a baseline applied under `--ide-safe` (or anywhere) is no longer silent — stderr prints `baseline: <n> violations suppressed by <path>` and `--progress` emits a `BaselineApplied` event; both IDE hosts echo it as `[WARN]`. `assess` tool-error paths and SARIF output under a junctioned directory are handled (paths relativised to the workspace; only the target file/parent are checked for reparse points).
- **Visual Studio Extension (2026-09-29)**: a run that reaches the timeout boundary is published when its SARIF file already exists instead of being deleted (termination classified as `Terminated` / `AlreadyExited`; the exit code of a terminated process is `taskkill`'s, not the CLI's, so it is not interpreted and the Output pane says `[WARN] Terminated at the timeout after results were written; the exit code is not meaningful. See Error List.`); a second command during a run no longer wipes the rule inventory or misreports on Cancel; process start and consent hashing run off the UI thread; progress parsing no longer loses `HasSummary`/handshake to UI latency; closing the solution stops the run and clears the Error List, and a run finishing under another solution is discarded; validate exit 1 with a summary but no SARIF is explained as a failure to write results; exit 3 keeps the previous Error List items.
- **Visual Studio Extension (2026-09-29)**: Error List double-click now positions the caret at the SARIF line/column via `ErrorListProvider.Navigate` (the previous handler only opened the document). SARIF results with malformed fields are skipped individually instead of aborting the whole load; Error List is capped at 2 000 tasks per run with the truncation count reported; percent-encoded relative URIs are decoded; `assess` no longer shows the previous `validate` run's rule inventory.
- **Build (2026-09-29)**: the VSIX build's nested `dotnet publish -r win-x64` of the CLI rewrote nine committed `packages.lock.json` files (adding `win-x64` + ILLink.Tasks), which then failed the next `--locked-mode` restore with NU1004. The publish now uses `NuGetLockFilePath=obj\cli-publish.packages.lock.json`, so committed lock files stay untouched.
- Analyzer package missing `DataGuard.Core.dll` at load time (bundled dependency closure).
- `oracle-check` exit code (returns 1 on failure); DG098/DG099 descriptor registration (Warning, not DG002 fallback).
- Docker image baking wrong version (VERSION build-arg); fake `github.com/DataGuard/DataGuard` URLs in 4 packages.
- MySQL LONGTEXT `CHARACTER_MAXIMUM_LENGTH` overflow; Oracle DG007 byte-vs-char comparison; PG unnamed-parameter drop.
- Flaky AutoDetectionEngine tests: env var `DATAGUARD_CONNECTION_STRING` leaked from CredentialManagerFullTests via xUnit parallel execution; fixed with `[Collection("Sequential")]` + IDisposable cleanup on all env-var-sensitive test classes.
