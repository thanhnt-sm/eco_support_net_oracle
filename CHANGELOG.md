### Changed (red-team rec 20: Program.cs and ContractRules.cs split; config binding fixed)
- **CLI source layout**: `src/DataGuard.Cli/Program.cs` (3 041 lines) now only wires the root command (52 lines). Each command is in `src/DataGuard.Cli/Commands/` (`ValidateCommand`, `ScanCommand`, `VerifyShapeCommand`, `PreflightCommand`, `BaselineCommand`, `SnapshotCommands`, `InitCommand`, `HookCommand`, `ConfigCommands`, `OracleCheckCommand`, `MigrateCommand`, `AssessCommand`, `VersionCommand`, shared options in `CommonOptions`) and shared logic in `src/DataGuard.Cli/Services/` (`ConfigLoader`, `ContractAcquisition`, `ValidationRunner`, `SnapshotGuard`, `DatabaseVersionReader`, `OutputSinks`). The CLI's duplicate `ComputeSchemaHash` is gone (it uses `BaselineManager.ComputeSchemaHash`). No behavior change: 56 CLI invocations on a fixture (every `validate` format, `scan`, `snapshot`, `config`, `init`, `baseline`, `assess`, error paths and every `--help`) give byte-identical output, exit codes and files, SARIF included.
- **Rules source layout**: `src/DataGuard.Core/Rules/ContractRules.cs` is split into `ContractRuleBase.cs` and one file per rule; public type names and namespaces are unchanged. The SQL text helpers of `ColumnShapeMatchRule` moved to the internal `Rules/Sql/SqlTextScanner.cs` (the public `ColumnShapeMatchRule` helpers forward to it). The per-`$` `Substring(i)` + regex probe (O(n·#$)) and the per-character keyword `Substring` calls are replaced by index-based scanning: a 256 KB literal with 5 000 `$n` placeholders took 2.3 s and now takes about 0.1 s (guarded by a < 2 s test).
- **Config binding fixed**: the typed `.dataguard.yml` path never worked (`DataGuardConfiguration` is a positional record without a parameterless constructor), so every file fell back to top-level scalars and silently dropped the nested `Oracle:`/`SqlServer:` blocks, the `ExcludedProcedures`/`ExcludedEntities` lists and the `AuditKeyFile`/`RequireEncryptedCredentialStore` keys. A binding document now maps every key onto the record defaults; an empty value keeps the default (it used to become an empty string, so `DefaultSchema:` hid `Oracle.Owner`). The scalar mapping is only a last resort when the typed binding rejects the file.
- **`verify-shape --provider mysql`** uses `MySqlLiveQuerySchemaProvider` (was exit 2, "does not support live query schema verification").
- **Snapshot provider**: `baseline` now records `Provider` like `snapshot refresh`; `validate` treats an empty `Provider` in a format-4 snapshot as unusable (`UNEVALUATED`, exit 3) instead of skipping the provider check. Format 2/3 files keep the lenient behavior.
- **DG1291 printed once**: `validate` no longer repeats the extractor's `[WARN] DG1291 ...` line as `ACQUISITION: <path>: SQL literal ...`; the skipped literal still makes the result incomplete (exit 3 without `--allow-unevaluated`).
- **Dependencies**: `DataGuard.Core` drops the unused `Microsoft.Extensions.Diagnostics.HealthChecks` package (lock files regenerated). CI's benchmark job also builds `tools/benchmarks/DataGuard.Observability.Benchmarks`; `anti_garbage_guard.sh`/`preflight_agent_check.sh` no longer allow a root `benchmarks/` directory.

### Security (red-team D1/D2: credentials resolved through the provider, keyed audit chain)
- **CLI credential resolution (D1)**: database-backed commands resolve `--connection` → new `--connection-env NAME` (the name of an environment variable) → `DATAGUARD_CONNECTION_STRING` → `ZeroTrustCredentialProvider` (Azure Key Vault, AWS Secrets Manager, HashiCorp Vault as configured, `DATAGUARD_DATABASECONNECTION`, then the encrypted credential file) → `ConnectionString` from `.dataguard.yml` **only** with `AllowPlaintextConfigFallback: true`. **Breaking:** a plaintext `ConnectionString` in the config is now ignored by default with a one-line warning naming the key. `--connection` still works but prints `warning: a connection string on the command line is visible to process listings; prefer --connection-env`. Secret-store failures are logged at Warning with the store name (were Debug and silent). `--offline` and `--ide-safe` never consult secret stores; under `--ide-safe`, `--connection-env` is rejected unless `--allow-env-connection` is also given (the named variable then plays the role of `DATAGUARD_CONNECTION_STRING`).
- **AWS SDK out of Core**: `AWSSDK.SecretsManager` moved from `DataGuard.Core` to `DataGuard.Cli` (`DataGuard.Cli.Security.AwsSecretsManagerSecretStore`). Core exposes `ISecretStore` (built-in HTTP stores `AzureKeyVaultSecretStore`, `HashiCorpVaultSecretStore`) and a `ZeroTrustCredentialProvider` constructor that registers host stores; library hosts that set `AwsRegion` register their own store (a warning says so otherwise). New `ZeroTrustCredentialProvider.TryGetCredentialAsync`.
- **Encrypt at rest by default**: `EncryptConnectionStringAtRest` now defaults to `true` (DPAPI, macOS Keychain, Linux Secret Service via `/usr/bin/secret-tool`); without a backend the credential file falls back to owner-only plaintext with a warning, or fails with the new `RequireEncryptedCredentialStore: true`. `CredentialManager` takes an injectable platform decision for deterministic tests.
- **Keyed audit chain, single writer (D2)**: `FileAuditLogger` chains entries with HMAC-SHA256 when `DATAGUARD_AUDIT_KEY` or the new `AuditKeyFile` key is set (at least 16 bytes); otherwise SHA-256 as before. **Breaking (API):** `VerifyIntegrityAsync` returns `AuditIntegrityResult` (`Valid`, `Unkeyed`, `Tampered`, `KeyRequired`; `IsIntact`) instead of `bool`; an unkeyed entry after a keyed one is tampering. `CredentialManager` writes through the injected `IAuditLogger` (new `LogSecurityEventAsync`) instead of appending raw lines, so mixed writers keep one valid chain; writers re-read the chain tail under a per-path lock. Connection-string fingerprints are HMACs under a per-log random salt stored in the checkpoint header (`IAuditLogger.HashSensitiveValue`); `MaskValue` keeps at most four characters.
- **Manual mode without code execution**: `ManualContractSource` reads attributes through `System.Reflection.MetadataLoadContext` (new Core dependency, MIT) instead of `Assembly.LoadFrom`; nothing from the assembly runs and it never enters the default load context. A `ManualAssemblyPath` from the config file now requires `--allow-assembly-from-config` on `validate`/`baseline` (exit 2 otherwise); `--offline --assembly <path>` needs no flag; `--ide-safe` rejects the flag.

### Changed (red-team B4/D3: one validation pipeline, working plugins)
- **One rule composition and executor**: CLI `validate`, `baseline`, `snapshot refresh` and `snapshot diff --legacy-violation-diff` compose `ProviderRuleCatalog` rules (plus admitted plugins) with `BuiltInRuleDependencies.Create` and run them through `GraphValidationExecutor` (concurrent levels, or the new `ValidateSequentialAsync` when `EnableConcurrentValidation: false`), the same executor `ValidationPipeline` uses. New `ValidationPipeline.WithProviderRules(...)`, `ValidationPipeline.Rules`, `ProviderRuleCatalog.GetReadyRules/CreatePipeline/Compose`; a test asserts identical CLI/API rule plans for every provider. The sequential path now sorts violations like the concurrent one and records a throwing rule as `Failed` (CLI: `Validation failed: Validation incomplete: ...`, exit 1).
- **Config reaches the rules**: `ProviderRuleCatalog.Get` call sites pass `StrictProcedureContracts`, `DefaultSchema` and `DefaultPackage`; the YAML fallback mapper knows `StrictProcedureContracts` (previously ignored when the typed load failed), so `StrictProcedureContracts: true` turns catalog DG101/DG002/DG003 warnings into errors (exit 1).
- **Unevaluated contracts everywhere**: `ContractRuleBase` implements `IContractEvaluationStatusReporter` with `protected MarkUnevaluated(...)` (used by `LiveSqlShapeValidationRule`); `ValidationResult.UnevaluatedContracts` (and `IsClean` is false when any exist); `ConcurrentValidationEngine.StreamAsync(contracts, rules, unevaluated, ct)` reports them before the stream completes. `baseline`/`snapshot refresh` list them and never persist them; `snapshot diff --legacy-violation-diff` lists them and exits 3.
- **`RuleDependencyGraph`**: registering a different rule with an existing ID throws `InvalidOperationException` (same instance is idempotent; `ValidationPipeline.WithRules(new ParameterCountRule())` on the default pipeline now throws instead of being dropped); `WithDependency`/`RegisterDependencies` declare null placeholders (`DummyRule` deleted); all iteration is `StringComparer.Ordinal`. `BuiltInRuleDependencies` exposes `Edges`, `CreateDefaultRules()` (now includes the connectionless DG018, 11 rules) and `Create(rules)`.
- **Plugins work**: `RulePluginManager` reads `[ExportRule]` metadata (it read `[ExportMetadata]`, so every plugin had RuleId "" and only one survived); the manifest `ruleId`, `[ExportRule]` RuleId and runtime `RuleId` must match or the admission is rejected with the reason; an unversioned host (0.0.0.0) is compatible with every `MinDataGuardVersion` (logged). New `GetPluginRules(...)`. CLI `validate --plugins-dir <dir>` loads plugins through `PluginAdmission` with the default trust policy (signed provenance required; config `Plugins.AllowUnsignedLocal: true` opts in for local plugins); rejected plugins are reported like unavailable rules; `--ide-safe` rejects `--plugins-dir` (exit 2). `CustomNamingConventionRule` moved out of `DataGuard.Core` to `samples/plugins/DataGuard.Samples.NamingPlugin/` (not in `DataGuard.sln`).
- **Public API snapshot v4**: `ValidationPipeline.CheckDriftAsync` accepts version 4 snapshots (integrity-verified, `canonical-schema-v2`; new overload with current stored procedures); new `CreateBaselineAsync(violations, schema, storedProcedures, ...)` writes version 4 (empty procedures for tables-only input).
- **`IDialectAnalyzer` has callers**: DG010/DG011, MY001/MY002 and PG001/PG002 delegate to their checker through `IDialectAnalyzer.Analyze`.

### Changed (red-team H3, H4: snapshot v4, baseline fingerprints)
- **Snapshot v4** (H4; the plan's "snapshot v3", on disk `Version: 4` because version 3 already meant tables plus `canonical-schema-v1`): `snapshot refresh` persists tables with `Schema` and column `Charset`, `StoredProcedures` (parameters with direction, length, `HasDefault`, overload/sequence, result columns, ref cursor, `ReturnType`), `LengthSemantics` and `Charset`; `SchemaHash` (`canonical-schema-v2`) covers all of it. Snapshot mode now materializes the procedures and the real length semantics (the hard-coded `CHAR` is only the fallback for pre-v4 files). v2/v3 files still load (tables only) with a `snapshot has no stored procedures` warning.
- **`validate` snapshot checks** (H4): provider mismatch => `UNEVALUATED: snapshot provider 'x' does not match 'y'` (exit 3); `SchemaHash` recomputed over the loaded content and compared => `snapshot integrity check failed` (exit 3); age above `SnapshotMaxAgeDays` (new config key, default 90) => warning. `snapshot diff` checks integrity before connecting, reports added/removed/changed tables and procedures, and now warns on database major.minor drift (the previously unused version comparison). `snapshot show` prints table/procedure counts and the integrity status.
- **Baseline fingerprint v2** (H3): entries carry `Fingerprint` (SHA-256 of rule id, sorted structured `Properties` without volatile keys, repo-relative path plus `sqlHash`) and `Count`; the baseline is a multiset, so a second identical finding is reported. Legacy `RuleId:Message` entries still match (R6) and `validate` prints `baseline contains N legacy entries; run 'dataguard baseline' to upgrade`. `dataguard baseline` no longer filters through the existing baseline while rewriting it and, without a connection, uses the same default snapshot as `validate`. A file rename changes the fingerprint.
- **DG004/DG017 properties** (H3): DG004 carries the full sorted `columns` list, `entity` and `sqlHash` (the message keeps `Take(5)` for display); DG017 carries `sqlHash` and `table`, so two `SELECT *` sites are no longer one baseline entry.
- **SARIF**: every result has `partialFingerprints["dataguard/v2"]`, equal to the baseline fingerprint.
- **Large baseline load**: the >1 MiB memory-mapped path reads exactly the file length instead of the page-rounded view capacity (trailing NULs failed JSON parsing where the capacity is rounded, e.g. Windows).

### Fixed (red-team C3, C5, H5, H10, H11: rule correctness)
- **Phantom rules split and schema-aware** (C3, H10): `PhantomIdentifierRule` is replaced by `PhantomTableRule` (DG015) and `PhantomColumnRule` (DG016) sharing a tokenizer-based analyzer. Catalog tables are indexed by `(schema, name)` and bare name, so SQL Server tables keyed `dbo.Orders` no longer flag every `FROM Orders`; comments and literals are masked; CTE lists, `WITH RECURSIVE`, TVFs, `#temp`/`@tvp`, cross-database names, `DUAL`, `sys.*`, `EXTRACT(... FROM ...)`, `TRIM(... FROM ...)`, `IS DISTINCT FROM`, output aliases and multi-table unqualified columns are no longer reported. `--skip-rules DG016` now targets only phantom columns.
- **DG005 nullability** (C5): uses `PropertyDescriptor.IsNullable`, resolves the column inside the entity's own table (schema-qualified names supported, no cross-table merging) and reports both directions: NOT NULL column ↔ nullable property and nullable column ↔ non-nullable property.
- **DG013/DG010/DG011 on stored-procedure descriptors** (H5): Oracle dialect rules skip descriptors with `IsStoredProcedure`, so `CommandText = "PKG.PROC"` + `CommandType.StoredProcedure` is no longer reported as SQL Server `EXEC` syntax.
- **DG019 replaces the second meaning of DG016** (H11): `RawSqlParseStatusRule` now emits `DG019` ("Raw SQL Parse Error"). `ProviderRuleCatalogTests` asserts rule IDs are unique per provider and that each rule emits only its own ID.
- **C# SQL extractor** (H9, C1 extractor half, `[SkipContractCheck]`): stored-procedure call sites (ADO `CommandType.StoredProcedure`, Dapper `commandType:`, `EXEC`/`CALL`/PL/SQL `BEGIN p(...); END;` text) now carry `ProcedureName`/`ProcedureSchema`/`ProcedurePackage` and one parameter per argument with `ClrType` and `CallSiteDirection`; `IsSqlString` requires a statement shape (CQRS `UpdateProfileCommand("Please update ...")` and `base("DefaultConnection")` no longer become contracts); `QueryFirst*`, `SqlQuery*`, `ExecuteSql*`, `conn?.Query<T>` and target-typed `new SqlCommand(...)` are recognized; the last `CommandText` before execution wins; interpolation holes become `@name` placeholders; `Query<string>` and get-only/non-public properties no longer produce expected properties; descriptor ids are `project-sql:{repo-relative path}:{span}:{sql hash}`; references come from the project's `project.assets.json` when restored. `[SkipContractCheck]` on a method or enclosing type skips the call site, and unreadable files, C# syntax errors, oversized literals and skips are exposed as `ProjectCSharpSqlSource.Diagnostics`. Bare procedure names are no longer accepted by `IsSqlString` (use `IsProcedureName`).
- **Connection provider inference**: `ConnectionDiscovery.InferProviderFromConnectionString` scores provider-specific keys instead of taking the first match, so `Data Source=...;Initial Catalog=...;User Id=...` is SQL Server (was Oracle) and `Server=...;Uid=...;SslMode=...` is MySQL (was SQL Server); a tie is `unknown`.
- **Contracts** (preparation for stored-procedure matching): `ParameterDescriptor.HasDefault`, `ColumnDescriptor.Charset`, `DatabaseTableDescriptor.Schema`, `StoredProcedureDescriptor.ReturnType`, `RawSqlDescriptor.ProcedureSchema`/`ProcedurePackage` added as optional trailing members.

### Fixed (red-team C6, H7, H8: provider catalogs and length semantics)
- **Oracle package catalog** (C6): `AllArgumentsReader.GetProceduresAsync` reads `ALL_ARGUMENTS` (`DATA_LEVEL = 0`) together with `ALL_PROCEDURES` header rows in one statement and groups by `(package_name, object_name, subprogram_id)`.
  - Every package overload is kept, including 0-argument subprograms. Oracle 18c+ has no argument row for those.
  - `DEFAULTED` maps to `HasDefault`, and the function return row maps to `ReturnType`.
  - `GetProcedureNamesAsync` no longer references the non-existent `ALL_PROCEDURES.PACKAGE_NAME`, which raised ORA-00904.
  - An empty package filter now means standalone units only.
  - Stored-procedure ids are `oracle:{OWNER}.{PACKAGE|_}.{NAME}#{SUBPROGRAM_ID}` with `PackageName` set. **Breaking for baselines keyed on the old Oracle ids.** `DefaultPackage` no longer filters the catalog.
- **Oracle NLS facts**: `NLS_CHARACTERSET`/`NLS_NCHAR_CHARACTERSET` are read from `nls_database_parameters`; the session view never had them. `MAX_STRING_SIZE` comes from `v$parameter`, falling back to `STANDARD`. The schema descriptor carries these facts, and each character column gets `ColumnDescriptor.Charset`.
- **`Oracle.DescribeRefCursors`** (new, default `false`): when enabled, catalog extraction **executes** every procedure or function that returns a REF CURSOR, binding NULL to its IN parameters, and records the cursor's `ResultColumns`. `ReturnsRefCursor` now always comes from the catalog.
- **Oracle DG008** (H8): the byte factor is now `bytesPerUtf16Unit(charset, IsUnicode)` (AL32UTF8 3, AL16UTF16 2, single-byte 1, unknown 3); the old fixed factor was 4.
  - CHAR-semantics columns are checked against `min(CHAR_LENGTH × maxBytesPerChar, 2000|4000|32767)`.
  - `IsUnicode(false)` is honored through `Annotations["IsUnicode"]`, which `EfModelSource` now emits.
  - Column lookup tries the EF column name, then `CUSTOMERID`, then `CUSTOMER_ID`.
- **Length rules on schema-qualified entities** (H7): Oracle, PostgreSQL and MySQL length rules resolve `SCHEMA.TABLE` entity names by `(schema, name)` instead of comparing the whole string. Before, they were silent for every schema-qualified entity.
- **PostgreSQL catalog**:
  - `RETURNS TABLE` columns (`proargmodes 't'`) become `ResultColumns`.
  - `pronargdefaults` sets `HasDefault` on the trailing inputs, and unnamed arguments are named `p{i}`.
  - Ids are `postgres:{schema}.{name}({in-arg types})` instead of the OID.
  - Materialized views are included, and table keys are case-sensitive.
  - PG003 reports at most one finding per property, without the UTF-8 byte check, and tries snake_case column names.
- **MySQL catalog**:
  - Functions are read, with `ReturnType` and Id `mysql:{schema}.{name}#function`.
  - An empty schema means `DATABASE()` instead of every schema on the server.
  - Table keys follow `@@lower_case_table_names`, and the charset moves from `CharUsed` to `ColumnDescriptor.Charset`.
  - MY006 compares TEXT limits in bytes, and `utf8mb3` is 3 bytes.
  - MY005 is now a row-size check (65,535 bytes).
  - MY007 fires only for a string without MaxLength on a `varchar(n)`/`char(n)` column (Pomelo maps such a string to `longtext`).
- **SQL Server catalog**:
  - `nchar`/`nvarchar` `max_length` is converted to characters in `sys.parameters` and `sp_describe_first_result_set`, so `nvarchar(50)` gives `MaxLength = 50`.
  - One failing `sp_describe_first_result_set` no longer aborts extraction; that procedure gets `ReturnType = "unknown:<error>"`.
  - Schema tables are `Name` = bare table name plus `Schema`, and the phantom/nullability table index uses `DatabaseTableDescriptor.Schema`.

### Fixed (red-team C2, C4: CLI exit gates)
- **Unavailable rules no longer block `validate`** (C2): a rule the provider cannot evaluate (`DG012` on Oracle, `PG004` on PostgreSQL) prints `Rule <id> not evaluated: <reason>` once on stderr and no longer forces exit 3. `--fail-on-unavailable` or config `FailOnUnavailableRules: true` restores exit 3; `--skip-rules` is applied first.
- **Empty-pass gate** (C4): `--provider` and config `DefaultProvider` accept only `sqlserver`, `oracle`, `mysql`, `postgresql` (`postgres`) on every command, otherwise exit 2; `--config` pointing to a missing file exits 2 (was silent defaults; still a warning under `--ide-safe`, because IDE hosts always pass the workspace path); a config value of the wrong type exits 2; unknown top-level keys print a warning, exit 2 with `StrictConfig: true`.
- **Ground-truth gate**: `validate` with no schema, stored procedure or entity contract (inline SQL from `--project` only) prints `UNEVALUATED: no ground truth ...` and exits 3. **Breaking for lint-only CI runs**: add `--allow-syntactic-only`. `--ide-safe` runs and `--format contracts|yaml|typescript` are not gated.
- **Default snapshot**: without a connection or `SnapshotFilePath`, `validate` uses `.dataguard-snapshot.json` next to `--config`, else in the current directory, and prints `Using snapshot <path>`.
- **`--offline` semantics** (risk R3): bare `--offline` now means Snapshot mode and drops any connection (was Manual mode without an assembly, or exit 1); `--offline --assembly <path>` is unchanged (Manual).

### Changed (red-team H1, H2: unevaluated semantics)
- **One `Unevaluated` outcome for database failures**: `ILiveQuerySchemaProvider.DescribeResultSetAsync` now returns `LiveSchemaResult` (`Columns`, `Status` = `Described | Failed | Unsupported`, sanitized `Error`); `DescribeColumnsOrThrowAsync` keeps a column-list form for callers such as `verify-shape`. **Breaking for custom `ILiveQuerySchemaProvider` implementations.**
- **No fabricated columns** (H1): the Oracle and PostgreSQL live describers return `Failed`/`Unsupported` instead of inventing `VARCHAR2`/`text` columns from the SQL text. The syntactic extraction survives only behind the constructor flag `allowSyntacticFallback` (default false), and even then the status is never `Described`.
- **DG020 is no longer a warning** (H2): a query whose shape cannot be described is recorded as an unevaluated contract (`DG020 <contractId>: <reason>`), not as a `Warning` that exits 0. `validate` prints `UNEVALUATED: <n> contract(s) could not be evaluated:` with one line per contract and exits 3. **Breaking for CI runs whose live describe fails**: new `--allow-unevaluated` lists them but exits by violations; `--ide-safe` implies it.
- **MySQL live describe** (H2): new `MySqlLiveQuerySchemaProvider` (`CommandBehavior.SchemaOnly` + `GetColumnSchema()` on a `WHERE 1=0 LIMIT 0` wrapper, read-only session, denylist and MySQL lexical guard); `ProviderRuleCatalog` registers it for `mysql` instead of skipping the live rule silently.
- **Partial ModelSnapshot parse is visible**: `EfModelSource.ParseModelSnapshotWithDiagnostics`/`ExtractFromModelSnapshotWithDiagnosticsAsync` keep the parsed entities and return `AcquisitionDiagnostic` entries for skipped configurations; `validate` prints `ACQUISITION: <path>: <message>` and exits 3 unless `--allow-unevaluated`.
- **Engine**: `ValidationExecutionResult.UnevaluatedContracts` is filled from rules implementing `IContractEvaluationStatusReporter` on the concurrent, graph and sequential paths; it does not set `IsIncomplete`, so `ConcurrentValidationEngine.ValidateAsync` does not throw for it.

### Changed (red-team A1/R33: Core no longer references SQL Server)
- **SQL Server code moved to `DataGuard.SqlServer.Adapter`** (namespace `DataGuard.SqlServer.Adapter`, no type forwarders): `SqlServerStoredProcedureParser` and `RawSqlParser` (were `DataGuard.Core.Sources`), `SqlServerLiveQuerySchemaProvider` (was `DataGuard.Core.Rules`), `SqlServerTypeCompatibility` (was `DataGuard.Core.Rules.TypeCompatibility`). **Breaking for library callers**: reference the `DataGuard.SqlServer.Adapter` package and change the `using`. The adapter, which previously held only the ScriptDOM phantom analyzer, now holds all SQL Server code.
- **`DataGuard.Core` drops `Microsoft.Data.SqlClient` and `Microsoft.SqlServer.TransactSql.ScriptDom`.** Consumers that used SqlClient/ScriptDOM through Core's transitive references must reference them (or the SQL Server adapter) directly. `AWSSDK.SecretsManager` is unchanged in this step.
- **Adapters carry only their driver**: `DataGuard.Oracle.Adapter` (`Oracle.ManagedDataAccess.Core`), `DataGuard.PostgreSql.Adapter` (`Npgsql`), `DataGuard.MySql.Adapter` (`MySqlConnector`) and `DataGuard.SqlServer.Adapter` (`Microsoft.Data.SqlClient` + ScriptDOM) plus the Core `ProjectReference`; the copied Core package list (AWSSDK, Roslyn Analyzers/Workspaces, EF Core, SqlClient, ScriptDOM, `Microsoft.Extensions.*`, `System.Text.Json`) is removed. Every `packages.lock.json` is regenerated.
- **No SQL Server fallback in Core**: `TypeCompatibilityRegistry.Resolve` returns the new public `UnknownTypeCompatibility` (every pair `Unknown`, no findings) for an unregistered provider instead of the SQL Server table; the pre-3.1 Oracle map stays the `oracle` fallback. `ProviderRuleCatalog` registers `SqlServerTypeCompatibility` for `sqlserver`; library callers register or inject it. `LiveSqlShapeValidationRule` no longer creates a SQL Server describer itself: a connection string without an injected `ILiveQuerySchemaProvider` is reported unevaluated (DG020) for every provider.
- **DG019 receives T-SQL parse failures**: new Core seam `ISqlStatementParser` (`SqlStatementParseResult Parse(string sql)` with `IsValid`, `Error`, `Parameters`, `Columns`; default `NoOpSqlStatementParser`). `RawSqlParseStatusRule(ISqlStatementParser?)` reports raw SQL the injected parser rejects; `ProviderRuleCatalog` injects the adapter's ScriptDOM `TSqlStatementParser` for `sqlserver` only. Client placeholders (`:name`, `?`, `{0}`) are normalized first; stored-procedure calls and SQL whose connection hint names another provider are not parsed. Before this, DG019 only fired for `RawSqlParser` output, so C#-acquired malformed T-SQL passed silently.
