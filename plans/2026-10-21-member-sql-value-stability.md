# Member SQL value stability

Scope: bounded Core source proof for field/property SQL arguments. A member initializer does not establish the runtime value. Mutable and readonly fields (including constructor/static-constructor reassignment and cross-file partial declarations), auto-properties, block getters and runtime/virtual property dispatch remain unknown. No getter or application code is executed; no constructor interpreter or universal C# evaluator is introduced.

Allowed values remain literals, semantic string constants, stable locals from proved values, and source expression-bodied nonvirtual/nonoverride/nonabstract string properties whose body Roslyn proves a constant string. Property bodies are never recursively evaluated. Qualified nonconstant members must propagate rejection; qualified constants retain compiler proof. Source maps repeat the same proof gate and never publish a rejected initializer location as executable SQL.

The optional unreferenced member inventory is narrowed to const fields. An unused readonly initializer is no longer represented as an executable SQL contract; no acquisition gap is emitted solely for that unused initializer. Recognized SQL argument, command constructor and CommandText uses remain visible acquisition gaps even for procedure names or non-SQL-looking initializer text. Ambiguous legacy API heuristics retain their existing SQL-role/evidence limitations.

Unknown string members inside interpolation/composition and stable-local aliases reject the SQL value conservatively; numeric interpolation remains placeholder-based. Nonconstant string members used purely as scalar holes may therefore reduce precision. This is an intentional bounded-proof tradeoff.

Implementation lane owns the resolver/member proof, readonly standalone pass, focused tests and this plan. Coordinator owns shared rejection state/diagnostic reason integration and CLI/English/Vietnamese documentation. The integrated candidate uses a private rejection enum: unstable locals retain `UnstableSqlValue`, while unknown members use the existing `UnresolvedSqlValue`; neither diagnostic includes SQL or private payloads. Preintegration failures below are historical evidence, not the current candidate status. See the [integration ledger](2026-10-21-incomplete-correctness-integration.md) for final verification and publication state.
