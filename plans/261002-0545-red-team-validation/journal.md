## 1. Context & Architectural Motivation

The DataGuard Visual Studio extension and Core validation pipeline required stabilization across three critical axes:
1. **Line Mapping & Caret Navigation Precision**: Diagnostic locations reported in SARIF 2.1.0 (1-based line/col) must map accurately to the Visual Studio `ErrorTask` grid (1-based) and editor text buffer caret navigation (`IVsTextView.SetCaretPos`, which is strictly 0-based), avoiding off-by-one errors.
2. **Stored Procedure Detection & Analyzer Coverage**: ADO.NET and Dapper stored procedure invocations (`CommandType.StoredProcedure`) must be captured accurately by Roslyn AST extraction in `ProjectCSharpSqlSource.cs` (handling positional overloads, standard object initializers, and C# 9 target-typed `new()`), and flagged by Roslyn analyzers in `DataGuard.Analyzers` without breaking the zero-dependency contract of `DataGuard.SqlClassification`.
3. **Validation Engine Concurrency & UI Progress Thread Safety**: `ConcurrentValidationEngine.cs` must enforce backpressure with bounded channels (`BoundedChannelFullMode.Wait`) and propagate rule faults cleanly, while `RuleInventory` in `DataGuard.VisualStudio` must remain strictly thread-safe under concurrent stderr writes, snapshots, and clears.

## 2. Key Technical Decisions & Design Rationale

### 2.1 Preserving SARIF 2.1.0 1-Based Coordinates Invariant
- **Decision**: SARIF output generated by `DiagnosticEmitter.cs` must remain 1-based per the SARIF 2.1.0 specification. Coordinate translation to 0-based buffer offsets belongs exclusively at the IDE presentation boundary in `ErrorListPresenter.cs:161-163` (`Math.Max(0, task.Line - 1)`).
- **Verification**: `NavigationTests.cs` and `SarifErrorListPublisherTests.cs` verify both 1-based display coordinates and 0-based caret buffer translation.

### 2.2 Roslyn AST Extraction for Stored Procedures & Target-Typed New
- **Decision**: Extend `ProjectCSharpSqlSource.cs` to detect both named (`commandType: CommandType.StoredProcedure`) and positional argument values. Add `BaseObjectCreationExpressionSyntax` traversal to inspect object initializers for `CommandText` and `CommandType`, accommodating C# 9 `new()`.
- **False-Positive Prevention**: Require `.EndsWith(".StoredProcedure")` or exact string match `StoredProcedure` to prevent arbitrary identifiers with suffix `StoredProcedure` (e.g., `myStoredProcedure`) from falsely triggering stored procedure classification.
- **Verification**: 20/20 tests in `RedTeamRegressionTests.cs` and 17/17 tests in `DataGuard.Analyzers.Tests.csproj`.

### 2.3 Concurrency & Lock Gate Protection
- **Decision**: Validate that `ConcurrentValidationEngine.StreamAsync` respects queue bounds via `BoundedChannelOptions(capacity) { FullMode = BoundedChannelFullMode.Wait }` and propagates exceptions via `channel.Writer.TryComplete(exception)`. In `DataGuardPackage.cs`, provide a dedicated lock object (`ruleInventoryLock`) guarding all `RuleInventory` access points.
- **Verification**: High-parallelism simulation in `ConcurrentValidationExecutionTests.cs` and multi-threaded race simulation in `RuleInventoryTests.cs`.
