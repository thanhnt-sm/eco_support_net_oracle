## Verified OK

Hunt 1 — behaviour vs original
- Reservation leaks: every early return in `RunCliAsync` (`Commands.cs:76-89`) calls `ReleaseReservation`; exceptions before the inner try hit the outer `catch { Release; throw }` (`:160-164`); inner `finally` → `Complete(process)` (`:155`) clears active/cancelled/reserved atomically. `Process.Start()` failure inside `StartAndRegister` is caught by the inner catch and released. No leak path found.
- State machine `processGate/commandReserved/cancelledProcess` → `CliProcessRegistry` is a 1:1 port; `ShouldRecordCancellation`, `DecideCancellationSuppression`, `ShouldForceReleaseFailedTerminationReservation` bodies unchanged. Timeout/drain/close sequencing (3 s grace → `CloseStreams` → 500 ms → faulted-continuation swallow) identical.
- Dispose ordering identical (detach → stop → dispose → unadvise → ErrorListProvider). `_ruleInventory` now also cleared for assess (spec #8). Banner now precedes `Start()` (original wrote it after) — strictly better for pipe back-pressure.
- `ExitCodeExplainer` preserves original mappings; adds validate-3 wording, validate-1-without-summary, assess-2.

Hunt 2 — trust gate
- Consent-before-run is acceptable and preferable: consent is to the (directory, config-hash) pair, not to run success; recording after success would re-prompt on every CLI failure.
- `ShellSettingsManager` constructed at `DataGuardPackage.cs:72` after `SwitchToMainThreadAsync` at `:57`; `ShowMessageBox` at `Commands.cs:182` after the switch at `:181`. `fromBuild` never prompts (`:175-179`); assess is gated too.
- Key = SHA-256(`UPPER(fullpath)|sha256(config)|"absent"`); no collision surface; unreadable config hashes to a distinct sentinel and re-prompts once readable.

Hunt 3 — ide-safe completeness (`Program.cs:186-480`, `2118-2272`, `2272-2360`)
- `Apply` runs right after `ResolveCommandConfiguration` (env var already merged into `ConnectionString`), before every consumer. Forced Snapshot + null connection → `BuildContractsAsync` takes only the `ProjectCSharpSqlSource` + snapshot-read branch; every DB branch is guarded by `!IsNullOrEmpty(ConnectionString)`. `ManualContractSource` unreachable. EF options rejected before `ResolveEfSnapshotSource`.
- `SnapshotFilePath`/`BaselineFilePath`: read-only (`BaselineManager.LoadAsync` never writes; `MigrateBaselineAsync` only called from the `baseline` command). `summary.json` is written next to `--output` = VS temp dir, not a repo path. `AutoDetect*`/`EnableSmartDefaults`/`WithSmartDefaults` are consumed only by `AutoDetectionEngine`/`PublicApiSurface`, not the validate handler. `DefaultProvider` only selects the rule catalog (oracle/postgres → exit 3, documented deferred).
- `ProjectCSharpSqlSource`: Roslyn parse only; `MetadataReference` from `AppDomain.CurrentDomain.GetAssemblies()` (`:114-117`), never from repo DLLs; `ScanDirectory` skips reparse points and bin/obj/VCS/.vs dirs. No `Microsoft.Build`, `ProjectCollection`, `NuGet.*` anywhere under `Core/Assessment` or `Core/Sources`; only network client in assess is `OsvAdvisoryClient`, gated by the rejected flags. `RulePluginManager`, `CredentialManager`, `TelemetryCollector` are not referenced from `Program.cs`.

Hunt 4 — `ResolveSarifArtifactUri` (probed on .NET Framework)
- `file:///D:/repo/%2e%2e/%2e%2e/Windows/x` → `LocalPath` already `D:\Windows\x` → rejected by containment. Relative `%2e%2e` → `UnescapeDataString` + `GetFullPath` collapses → rejected. `\\?\` → either `ArgumentException` (legacy handling, caught → null) or unnormalised prefix that fails `StartsWith(D:\repo\)`; both safe. UNC `file://server/...` rejected via `IsUnc`. Case-insensitive containment and junction-inside-solution are byte-identical to original → not worse. Test `Load_PathTraversalAndRootedOutside_AreSkipped` covers the classic cases.

Hunt 5/6/7 — `IsIdeSafeUnsupportedMessage` matches the real 2.0.12 wording; `ide-safe: suppressed …` and `--offline is not allowed with --ide-safe` lines do not trip it. VSTHRD003 suppressions are safe for the reason in #4. No `ValueTuple` in any signature (tuple `switch` in `ExitCodeExplainer.cs:20` is method-body only), no `TextManager.Interop`, no `record`/`init` in the VSIX project; real `CreateVsixContainer=true` build passed.
