## Verified OK (no finding)

- **Handshake ordering**: `Program.cs:196-201` writes `ide-safe: active` before rejection, before `ProgressEmitter`, before config load; `:1672-1676` same for assess. Only System.CommandLine parse errors precede it (intended CliTooOld path). Unhandled exception after the line → stack trace on stderr, no SARIF → hosts fail closed ("produced no SARIF").
- **Config credential under `--allow-env-connection`**: `IdeSafePolicy.Apply:69-76` overwrites `ConnectionString` with the raw env value only when `environmentConnectionPresent`; config value never survives (matrix tests). `EncryptConnectionStringAtRest` forced off.
- **Scrub timing**: after `Apply`, before `GetRulesForProvider`/adapters; `CredentialManager`, `ZeroTrustCredentialProvider`, `AutoDetectionEngine` re-read paths all covered for the vars they use today.
- **Regex rewrite**: `\bSELECT\b\s*(.*?)\s*\bFROM\b` is a strict superset (`SELECT*FROM`, `SELECT(1) FROM` now match; empty/`*` tokens are skipped) — no rule-output drift; .NET NonBacktracking preserves lazy/leftmost preference (pinned by `ValidateAsync_SelectListStopsAtFirstFrom_WhenSubqueryFollows`); golden corpus green per report.
- **VS threading**: `SwitchTo(alwaysYield: true)` before `StartAndRegister`; consent hash and temp dir creation off the UI thread; `ProgressPump` single consumer, FIFO, drop-oldest with counted marker, one `SwitchToMainThreadAsync` per batch, flush exceptions logged and skipped; `FlushCompletion` always completes because `ParseStderrAsync`'s `finally` calls `Complete()` and streams are closed on every exit path (3 s / 5 s / 120 s).
- **Publish gate**: `Publish` requires exact first non-empty line; `CliTooOld` requires rejection-prefix ∧ no progress event ∧ exit 1; spoofed-path test present; solution-mismatch re-check runs after the gate and before Error List `Publish`.
- **Consent**: key = SHA256(UPPER(dir)|UPPER(sln)|configHash); Open Folder tolerated; `RequestCancelPending`/`ShouldStartAfterConsent` checked both after the modal and immediately before start; `RecordConsent` skipped when cancel pending.
- **Lifetime watcher**: advise/unadvise cookie, `OnBeforeCloseSolution` swallows handler exceptions, `Dispose` from package `Dispose`.
- **Constraints**: no `record`/`ValueTuple`/`TextManager.Interop` in `src/DataGuard.VisualStudio` (grep clean); all touched partials ≤ 198 lines (only pre-existing `DataGuardRulesOptionsPage.cs` 325 / `DataGuardLogger.cs` 357 exceed).
- **VS Code**: ack gate after cancel/timeout checks and before `loadDiagnostics`; `startFailed` prevents the double error; old-CLI regex anchored `^`; `--allow-env-connection` only for validate with a non-blank SecretStorage value (blank normalised to `undefined`, so no empty env var); host masking never returns non-host parts; confirmation runs before `nextReservation()`.
- **Workflows**: SHA pins preserved on every action; fork guard `env.ACT != 'true' && (github.event_name != 'pull_request' || head.repo.full_name == github.repository)` is correct for `pull_request`; artifact name carries the SHA; `cli-package` uses `-p:NuGetLockFilePath`/`RestoreLockedMode=false` so committed lock files are untouched; `release_version` output exists (`release.yml:69`); release order test → manifest patch → MSBuild → assert → stage; `create-github-release` and `publish-attestations` both `needs` `cli-package`.
- **Tests**: `ProgressPumpTests` deterministic (capacity test bounded by the flush gate: ≤ 17 lines flushed, drops guaranteed); `CliRunSessionLiveTests` Windows-only but the VS test project runs only on `windows-latest` (excluded from `DataGuard.CrossPlatform.slnf`); `AlreadyExited` test uses `WaitForExit()` not timing; `IdeSafeEnvironmentScrubTests` in a `DisableParallelization` collection; junction test `[WindowsFact]` with explicit `Assert.Fail` on mklink failure.
